Options are variadic arguments accepted by `Expect`, `Require`, and matcher methods. They
provide a consistent, composable mechanism for customising assertion behaviour without adding
parameters to every function signature.

All option constructors live in the `github.com/blugnu/test/opt` package.

```go
import "github.com/blugnu/test/opt"
```

---

## Expectation options

These options are consumed when creating the expectation (`Expect` / `Require`) and affect
how the overall assertion behaves.

### Naming an expectation

When an assertion fails, the name is prepended to the failure message, making it immediately
clear which value was wrong.

```go
// string shorthand — the idiomatic choice
Expect(user.ID, "user ID").To(Equal(expectedID))

// opt.Name — equivalent
Expect(user.ID, opt.Name("user ID")).To(Equal(expectedID))

// opt.Namef — formatted name
Expect(users[i].ID, opt.Namef("user[%d].ID", i)).To(Equal(expectedIDs[i]))
```

Failure output:

```text
user ID:
  expected: "abc123"
  got:      "xyz789"
```

### Marking an expectation as required

A required expectation halts the current test immediately on failure rather than recording the error and continuing.

```go
Require(err).IsNil()                              // always required
Expect(err).IsNil(opt.Required())                 // always required, via option
Expect(err).To(Equal(nil), opt.IsRequired(true))  // required via parameterised option
```

Use `Require(value).IsNil()` as the idiomatic choice; use `opt.Required()` or `opt.IsRequired(bool)`
to make an assertion required conditionally.

`opt.Required()` may be included in alternate option sets which are applied conditionally.
`opt.IsRequired(bool)` is useful when only the required status of an assertion varies among
an otherwise consistent set of options.

For example, in a table-driven test:

```go
    Expect(value).To(Equal(expected), tc.assertOpts...)

    // vs

    Expect(value).To(Equal(expected), opt.IsRequired(tc.isRequired))
```

## Matcher options

These options are forwarded to the matcher when passed to `To`, `ToNot`, `Should`, or `ShouldNot`:

```go
Expect(result).To(Equal(expected), opt.OnFailure("wrong result"))
```

### Custom failure message

`OnFailure` accepts a value to be used to report the test failure, replacing the test report
that would normally be generated by the matcher.

| Factory | Description |
| ------- | ----------- |
| `opt.OnFailure(string)` | fixed message (single-line) |
| `opt.OnFailure([]string)` | fixed message (multi-line) |
| `opt.OnFailure(func(opts ...any) []string)` | dynamic message — the function is called only when the test fails, and receives the same options passed to the matcher |
| `opt.OnFailure(<any>)` | produces a report that reads 'test failed with: <any>' |

> NOTE: if the string passed to `opt.OnFailure` contains newlines, it will be treated as a multi-line
> message and printed verbatim.

```go
// fixed string
opt.OnFailure("expected a valid response code")

// dynamic — called only when the test fails
opt.OnFailure(func(opts ...any) []string {
    return []string{
        fmt.Sprintf("request:  %s %s", method, url),
        fmt.Sprintf("expected: %d", report.Value(expectedCode, opts...)),
        fmt.Sprintf("got:      %d", report.Value(gotCode, opts...)),
    }
})
```

### String quoting

By default, string values in failure reports are enclosed in double quotes. Control this with:

```go
opt.QuotedStrings    // quote (the default)
opt.UnquotedStrings  // do not quote
```

## Option forwarding

Options passed to matcher methods are separated into expectation options and matcher options
automatically. You do not need to be careful about which layer an option belongs to — pass
everything in the same variadic list:

```go
Expect(got, "label", opt.Required()).To(Equal(expected), opt.OnFailure("wrong"))
```

Or pass them all to `To`:

```go
Expect(got).To(Equal(expected),
    opt.Name("label"),
    opt.Required(),
    opt.OnFailure("wrong"),
)
```

Both forms produce identical behaviour.

## All options at a glance

| Option | Where consumed | Effect |
| ------ | -------------- | ------ |
| `"name"` (string) | Expect / Require | names the expectation |
| `opt.Name("name")` | Expect / Require | names the expectation |
| `opt.Namef(s, args...)` | Expect / Require | formatted name |
| `opt.Required()` | Expect / matcher | halts test on failure |
| `opt.IsRequired(bool)` | Expect / matcher | conditional required |
| `opt.OnFailure(report)` | matcher | override the matcher failure report with a `string`, `[]string`, or `func(opts ...any) []string` |
| `opt.QuotedStrings` | matcher | string values are quoted (default) |
| `opt.UnquotedStrings` | matcher | disable string quoting |
